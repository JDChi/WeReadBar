# AGENTS.md — WeReadBar

macOS menu-bar app showing WeRead (微信读书) reading stats: a GitHub-style contribution heatmap plus today / streak / shelf tiles. Built with native Swift + SwiftUI.

## Quickstart

```bash
brew install xcodegen              # one-time, for project regeneration
xcodegen generate                   # regenerate WeReadBar.xcodeproj from project.yml
open WeReadBar.xcodeproj            # then ⌘R in Xcode
```

Headless build:

```bash
xcodebuild \
  -project WeReadBar.xcodeproj \
  -scheme WeReadBar \
  -configuration Debug \
  -destination 'platform=macOS' \
  CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO \
  build
```

## Architecture (read this before changing anything)

- **Entry**: `App/WeReadBarApp.swift` declares `MenuBarExtra` with the right-click menu (Refresh / Change API key / Quit). `LSUIElement = YES` in Info.plist → no Dock icon.
- **State**: `Data/StatsStore.swift` is the `@MainActor ObservableObject` source of truth. Owns the `WeReadClient` and orchestrates the heatmap pipeline. All `@Published` properties are `private(set)` — views observe but don't mutate directly.
- **Network**: `Data/WeReadClient.swift` is an `actor` wrapping `URLSession`. Single endpoint (`https://i.weread.qq.com/api/agent/gateway`), all params flat in the JSON body.
- **Onboarding**: `App/OnboardingWindowController.swift` owns a real `NSWindow` (NOT a SwiftUI `Window` scene — that one has a "can't reopen after user closes it" bug). See *Key gotchas* #7.
- **Token storage**: `Security/TokenStore.swift` persists the bearer token in macOS preferences (UserDefaults key `WeReadBar.apiToken`, plist at `~/Library/Preferences/com.local.wereadbar.plist`). Never read from env vars or `.zshrc` — this is an accessory app with no shell environment.

## Data pipeline (StatsStore.performRefresh)

1. Concurrently fetch `/shelf/sync` and `/readdata/detail?mode=annually`.
2. Update shelf count + currently-reading book.
3. Resolve heatmap data: `StatsStore.resolveHeatmap(annual:client:)`.
4. Build a 182-day array of `ReadingDay` ending today.
5. Compute derived stats: `todaySeconds`, `streak`, `weekTotalSeconds`.

`resolveHeatmap` prefers `annual.dailyReadTimes` when present; otherwise calls `stitchMonthly` which makes 7 sequential `/readdata/detail?mode=monthly&baseTime=<ts>` calls and stitches the per-day `readTimes` by key (UTC+8 midnight unix timestamps).

## Key gotchas — do NOT "fix" these

These were learned the hard way. Each one is the result of a real bug; if you change them, verify with the smoke tests below.

1. **`baseTime` is the only way to query a historical month.** The server silently ignores `year` and `month` params. See `WeReadClient.monthStartUTC8(for:)` and the docs in `~/.agents/skills/weread-skills/readdata.md`.
2. **`annual` mode `dailyReadTimes` is conditional.** When absent (we've seen it return `null` on real accounts), fall back to 7× `monthly` calls. Both code paths are kept in `StatsStore.resolveHeatmap`.
3. **All time fields are seconds.** Convert in the UI layer. The weread-skills docs explicitly warn "禁止误当成分钟或小时".
4. **"Active day" threshold is `seconds >= 60`**, not `> 0`. Matches the server's `readDays` rule.
5. **Shelf total = `books.length + albums.length + (mp ? 1 : 0)`.** Not just `books.length`. There's an explicit `ShelfResponse.totalCount` for this.
6. **`stitchMonthly` walks from a fixed `origin`**, not a mutated `cursor`. The original bug was `cursor = date - N months` per iteration, which compounded across loops and fetched the wrong months entirely.
7. **Onboarding must use AppKit `NSWindow`** (via `OnboardingWindowController`). SwiftUI `Window` scene + `openWindow(id:)` cannot re-show the window after the user dismisses it.
8. **Popover width is 600pt.** Heatmap math: cell=9pt + spacing=1pt × N gaps + 26pt weekday gutter must fit inside the 576pt content area. Don't bump the cell size without re-checking the arithmetic.
9. **Year-long view requires ≈ 13 months of data.** `stitchMonthly` walks back 12 prior months + current. Updating the column count requires also updating both the `stitchMonthly` range AND `buildDays` loop count (currently `-12..0` and `0..<371`).

## Common operations

| Task | Where |
|---|---|
| Change heatmap colors | `UI/HeatmapView.swift` → `Self.brand` static + opacity tiers in `color(for:)` |
| Change poll cadence | `UI/PopoverView.swift` → `Timer.publish(every:)` |
| Force monthly-stitch fallback for testing | env `WEREADBAR_FORCE_MONTHLY=1` |
| Add a new API endpoint | `Data/WeReadClient.swift` + new `Decodable` model in `Data/` |
| Change the menu-bar icon | `App/WeReadBarApp.swift` → `Image(systemName:)` |
| Clear stored token from terminal | `security delete-generic-password -s com.local.wereadbar.apikey` |

## Conventions

- **Concurrency**: `actor` for network (`WeReadClient`), `@MainActor` for state (`StatsStore`). Use `Task.checkCancellation()` in long loops. Single in-flight refresh via `refreshTask` + cancel-before-replace.
- **Logging**: `os.Logger` with subsystem `com.local.wereadbar` (see `wrLog` in `StatsStore.swift`). Never use `print` — this is an LSUIElement app, `stdout` doesn't reach the console.
- **Errors**: surface via `StatsStore.lastError`; the popover renders `ErrorBanner` when set.
- **Naming**: PascalCase Swift files matching the primary type. `Data/` models are `Decodable` only (no `Encodable` needed — we don't POST anything but raw gateway calls).
- **Dependencies**: none. System frameworks only (SwiftUI, AppKit, Security, Foundation, os).

## Smoke testing

```bash
# Build headless
cd ~/develop/weread-dashboard
xcodebuild -project WeReadBar.xcodeproj -scheme WeReadBar \
  -configuration Debug -destination 'platform=macOS' \
  CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO \
  build 2>&1 | grep -E "error:|BUILD"

# Run and capture logs
killall WeReadBar 2>/dev/null
log stream --predicate 'subsystem == "com.local.wereadbar"' --info --debug --style compact &
APP="/Users/chijiaduo/Library/Developer/Xcode/DerivedData/WeReadBar-*/Build/Products/Debug/WeReadBar.app"
"$APP/Contents/MacOS/WeReadBar" &
sleep 6 && killall WeReadBar
```

The log output should show:
- `bootstrap: UserDefaults has token (len=28)` (or `no token found` if first run)
- `performRefresh: shelf isOK=true, books=788, mp=true`
- `performRefresh: annual isOK=true, dailyReadTimes=-1, readTimes=12`
- 7× `stitch monthly baseTime=<ts>: got <N> keys` with contiguous baseTimes
- `stitchMonthly: bag has 172 unique keys`
- `performRefresh: built 182 days, <M> non-zero` (M should be > 0 and reasonable for the user's reading history)

## Out of scope (v1)

- Auto-update (Sparkle), notifications (`UNUserNotificationCenter`), global hotkeys
- Multiple accounts / key switching
- Sandbox + entitlements (run ad-hoc, sandbox off)
- Signing, notarization, App Store submission
- Local caching — every refresh re-hits the gateway
- Unit tests beyond headless compile check
- Custom AppIcon (use SF Symbol `book.closed.fill`)
- Localization (English-only strings)
